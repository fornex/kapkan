# Панель управления

Откройте **http://localhost:8080** в браузере, запущенном на узле с Kapkan. Когда вы под
атакой, в первую очередь смотрите на баннер **Live mode** (Kapkan действительно анонсирует
или только наблюдает?) и на список **Активные и недавние атаки** (что атакуют и насколько сильно).

Веб-интерфейс встроен прямо в сам бинарный файл `kapkan`, поэтому ничего дополнительно
устанавливать или разворачивать не нужно — один и тот же процесс обслуживает панель
управления, JSON API и метрики Prometheus.

<Callout type="info" title="Один бинарный файл, один слушатель">
Панель управления, JSON API и `/metrics` обслуживаются одним и тем же процессом по одному
и тому же адресу. Нет отдельного веб-сервиса, который нужно разворачивать или поддерживать
в синхронном состоянии.
</Callout>

## Где она находится

Панель управления обслуживается по пути `/` по тому же адресу, что и REST API — это значение
`api.listen` из вашей конфигурации. При значении по умолчанию `127.0.0.1:8080` вы открываете
её по адресу [http://localhost:8080](http://localhost:8080).

Поскольку по умолчанию привязка идёт к `127.0.0.1`, панель управления доступна только с самого
узла Kapkan — если открыть `localhost:8080` на собственном ноутбуке, вы ничего не увидите. Чтобы
посмотреть её со своей рабочей станции, пробросьте порт через SSH, а не меняйте привязку
`api.listen` на публичный адрес:

```bash
ssh -L 8080:127.0.0.1:8080 user@kapkan-host
```

Затем откройте [http://localhost:8080](http://localhost:8080) на своей рабочей станции.
(Чтобы привязать слушатель к публичному адресу, сначала нужен API-токен — см. оговорку об
[аутентификации](#аутентификация) ниже.)

Чтобы обслуживать только JSON API и метрики без интерфейса, отключите его:

```yaml
api:
  listen: "127.0.0.1:8080"
  dashboard: false   # serve the JSON API and /metrics only
```

При `api.dashboard: false` конечные точки `/api/v1` и `/metrics` продолжают работать — перестаёт
обслуживаться только оболочка встроенного интерфейса.

## Что она показывает

Панель управления опрашивает JSON API и отображает всё, что Kapkan отслеживает в памяти:

- **Live mode** — запущен ли экземпляр в режиме dry-run или в боевом (live), чтобы вы могли
  с первого взгляда понять, будет ли обнаруженная атака действительно анонсирована.
- **Активные и недавние атаки** — атаки, происходящие в данный момент, а также недавно
  завершившиеся, каждая со своей классификацией типа атаки (например, усиление через NTP/DNS
  или SYN-флуд — см. страницу [Обнаружение](/docs/detection) о том, что означает каждый тип) и
  доминирующими источниками, портами и протоколами, зафиксированными по выборкам потоков.
- **Топ источников (Top talkers)** — снимок отслеживаемых хостов с показателями по каждому
  направлению и обученными базовыми уровнями (baselines), чтобы вы могли видеть, кто шумит
  громче всех и как это соотносится с нормой.
- **Hostgroups** — ваши именованные группы префиксов и их состояние.
- **Узлы очистки (Scrubbing nodes)** — показываются только когда вы используете [управляемые
  узлы очистки](/docs/scrubbing#управляемые-узлы-очистки): живость каждого узла (он жив, потому что
  продолжает опрашивать правила), сколько блокировок отводят на него, а также его собственные
  сообщённые нагрузка, отбрасывания, версия и флаг dry-run — сообщённые столбцы так и помечены,
  потому что самоотчёт узла носит справочный характер и никогда не является источником его живости.
- **Edge** — показывается только когда настроены [граничные узлы](/docs/edge):
  каждая зона [файла зон](/docs/zones), с её частотой запросов по всему парку, узлами, на
  которых она только наблюдает, и столбцом вызова — *выкл.*, *предпросмотр* (ступень спросила бы, но
  лишь наблюдает, на каждом узле) или режим зоны с узлами, на которых он действует всерьёз (рычаг
  показывается как этот режим), — а также вызовом на всю зону с его причиной (триггер `zone-rps`
  узла), плюс панель **Кто получил бы проверку**: источники, для которых узлы показали бы вызов или
  отказ, самые активные первыми, с узлами, которые каждого видели. Прочитайте её, прежде чем ступень
  зоны заработает всерьёз; представление говорит *частично*, когда узлу пришлось отрезать часть
  этого набора, и предупреждает, когда узлы вырезали из своих отчётов целые зоны. Столбец
  **HTTP/3** читает состояние [HTTP/3](/docs/zones) зоны: *выкл.*, когда зона его не просит и по
  нему не обслуживается; *вкл. · 42% · 3/3* — когда её обслуживают по HTTP/3 все узлы, которые о
  ней отчитались, с долей последнего окна, пришедшей по HTTP/3 (процент опускается, если в окне не
  было запросов); *вкл. · 2/3 готовы* в оформлении «только наблюдение» — когда зона просит HTTP/3,
  а какой-то узел обслужить её по нему не может: наведите курсор на ячейку, чтобы увидеть, какие
  узлы обслуживают её по TCP и почему (*собрано без модуля HTTP/3*, *HTTP/3 отключён на узле* или
  *проверка готовности не удалась*), вместе с любым бюллетенем, который подняла проба этого узла; и
  *выкл. · 2 узла ещё обслуживают* — когда файл зон HTTP/3 уже не просит, а на узле ещё поднят
  слушающий сокет QUIC, потому что файл и парк расходятся до следующего поколения.
  **Щёлкните по строке зоны**, чтобы открыть под таблицей её сохранённую историю — см.
  [История зоны](#история-зоны) ниже.

  Столбец **Узлы** читает [размещение](/docs/edge#размещение-зон-по-узлам) зоны, а не число узлов,
  которые о ней сейчас отчитываются: `2/2` — это *из двух узлов, на которых зона размещена, живы
  оба*, `0/1` с красным бейджем **НЕ ОБСЛУЖИВАЕТСЯ** — это сигнал тревоги, что за размещённой зоной
  не стоит ни одного живого узла, а прочерк — это зона, которую вообще не покрывает ничья область
  размещения (предупреждение `kapkan -check-config`, а не авария). Наведите курсор на ячейку, чтобы
  увидеть имена узлов; под ней — для токена без области — стоит хост-группа зоны. Строки, которые
  завёл файл, но о которых не отчитался ни один узел, показывают прочерки вместо нулей — измеренный
  ноль и *ничего не измерено* суть разные ответы — и объясняют причину в столбце вызова, читая
  размещение, а не число отчётов: *только проксирование* для зоны в `policy.mode: none`,
  *ни один живой узел не обслуживает* для решающей зоны, все размещённые узлы которой лежат или
  которую не покрывает ничья область, и *отчёта пока нет* для зоны, чей размещённый узел жив, но о
  ней не упомянул, — свежий старт, отчёт старше окна или зона, которую узел вырезал из отчёта.

  При [мультиарендности](/docs/multi-tenancy) токен без области видит ещё и `tenant` каждой зоны
  под её именем, а над таблицей — ряд **кнопок с арендаторами** (подписанный **Арендатор**),
  который сужает до одного клиента и зоны, и панель **Кто получил бы проверку** (запоминается на
  сессию браузера; выбор, который больше не называет ни одного арендатора на экране, забывается, а
  не остаётся, чтобы включиться самому). Токен, привязанный к арендатору, видит ровно свои зоны —
  без этих кнопок и без баннера:
  пометка *видно только токенам без области* оставлена для мозга, который слишком стар, чтобы
  ответить на такой запрос вообще.
- **Узлы edge** — собственный инвентарь парка рядом с его зонами, показывается при том же условии.
  По строке на каждый настроенный узел: жив он или **ПОТЕРЯН** (единственный признак живости —
  опрос зон), агентские токены, [привязанные к нему](/docs/authentication#привязка-агентского-токена-к-его-узлу),
  и токен, который последним опрашивал за него, его область размещения и сколько зон эта область на
  него кладёт, а также — из собственного отчёта узла, с пометкой *(по отчёту)*, как и в столбцах
  узлов очистки, — его версия Kapkan, терминатор, которым он управляет, с действующим поколением,
  готовность этого терминатора к HTTP/3 и сертификаты, которыми он владеет, — жёлтые за 30 дней до
  истечения и красные за семь. Узел, у которого нет собственного токена, несёт жёлтый бейдж **общий
  токен**, пока хоть один агентский токен не привязан, а баннер сверху называет эти токены:
  непривязанный агентский токен может опрашивать и отчитываться за *любой* узел парка. Инвентарь
  называет токены и области размещения, поэтому виден только токенам без области; токен с областью
  видит на его месте ту же пометку *видно только токенам без области*, что и в инвентаре узлов
  очистки.
- **Таблица блокировок** — все блокировки, активные и исторические (со столбцом узла очистки, когда
  узлы настроены).
- **Трафик / Отчёты (Traffic / Reports)** — графики входящего/исходящего трафика в реальном
  времени, построенные на буферах скоростей в памяти, плюс раздел **Исторические отчёты
  (Historical reports)**, который читает сохранённые таблицы ClickHouse, когда хранение включено.
- **Управление** — те же действия, что предлагает API: **ручная блокировка / снятие блокировки** адреса и
  **перезагрузка конфигурации** (эквивалент отправки `SIGHUP`).

Хранение нужно двум частям панели управления: разделу **Исторические отчёты (Historical
reports)** на представлении Трафик / Отчёты, а на представлении Edge — карточке
[История зоны](#история-зоны) с её таблицей источников и карточке **События парка**. И то и другое
заполняется только тогда, когда включено [хранение в ClickHouse](/docs/storage), а в противном
случае отображает помеченный плейсхолдер с пояснением, как его включить.

<Callout type="success" title="База данных не требуется">
Панель управления полностью строится на состоянии движка, хранящемся в памяти. Историческое
хранение потоков — это отдельная, опциональная возможность; она не нужна для просмотра текущих
атак, топа источников или блокировок.
</Callout>

## История зоны

Всё остальное на представлении **Edge** — это последние десять секунд. Щелчок по строке зоны
открывает под таблицей её сохранённую историю за **1 ч**, **24 ч** или **7 дн.** — тот же вопрос,
заданный о периоде, а не об окне. Карточка читает [историю граничных
узлов](/docs/api#get-apiv1edgehistory), так что ей нужно [хранение в
ClickHouse](/docs/storage#история-граничных-узлов); при выключенном хранилище она показывает тот же
помеченный плейсхолдер, что и представление Трафик, и никогда не ошибку. Повторный щелчок по строке
или **Закрыть** её сворачивает.

В карточке два графика, а когда есть что рисовать по HTTP/3 — три:

- **Запросов/с** — окна узлов, просуммированные в корзины (минута, десять минут или час — под
  выбранный диапазон) и поделённые на настоящую длину окон, попавших в каждую из них.
- **Отказано или было бы** — отказы плюс вызовы плюс «отказало бы» плюс «проверило бы», чтобы
  ступень, которая только показывает, и ступень, которая действует всерьёз, считались по одной оси.
  Тег *предпросмотр* говорит, что **сейчас** ступень не действует всерьёз ни на одном узле; а
  заголовком **Было бы отказано** график становится только тогда, когда и в самом периоде нет ни
  одного настоящего отказа, — ведь ступень, переведённая в наблюдение час назад, оставляет
  настоящие отказы в часах позади себя.
- **Доля HTTP/3, %** — показывается, только когда HTTP/3-запросы действительно видела хоть одна
  корзина: ровная нулевая линия под зоной, до которой никто не доходит по QUIC, читалась бы как
  измерение, а не как отсутствие.

Под графиками — итоги периода: больше всего узлов, замеченных отчитывающимися в одной корзине,
запросы, отказы (настоящие или показанные), число 4xx / 5xx и та ширина корзины, которую движок
применил на самом деле: он **поднимает** запрошенный у него шаг, когда иначе в диапазон попало бы
больше 5 000 корзин, так что эта цифра называет корзины, на которые вы смотрите.

Под карточкой раздел **Кто получил бы проверку — за 1 ч** (или **24 ч** / **7 дн.** — вслед за
выбранным диапазоном) перечисляет источники периода, о которых есть что сказать, самые активные
первыми: самое сильное, что с каждым из них сделал хоть один узел (*отказано*, *проверен*,
*отказало бы*, *проверило бы* — теми же бейджами, что и в живой таблице), его запросы, сколько окон
и узлов его видели и когда его видели впервые и в последний раз. Это тот самый вопрос, который
стоит задать, прежде чем ступень зоны заработает всерьёз, — за сутки, а не за десять секунд.

Завершает представление для токенов без области карточка **События парка**: что мозг увидел
изменившимся за последние 24 часа, свежее сверху, — узел потерян или вернулся, версия,
переключившийся флаг dry-run, собранный документ, установленное или отклонённое поколение, живость
терминатора, состояние HTTP/3, выпущенный, обновлённый или пропавший сертификат, включившийся или
снятый вызов на всю зону, ушедшие за допуск часы узла, отчёт, который пришлось урезать.
Токен, [привязанный к арендатору](/docs/multi-tenancy), этой карточки не видит вовсе: события
называют узлы. История же и её источники, наоборот, доступны арендатору по его собственным зонам —
чужая зона получает отказ, и карточка просто не появляется.

<Callout type="info" title="Читается по требованию, а не на опросе">
История зоны и её источники читаются, когда вы открываете зону или переключаете её диапазон;
события парка — пока представление Edge на экране у токена без области, открыта зона или нет. Все
три — не чаще раза в десять секунд и ни одно из них не на трёхсекундном опросе консоли: они
обращаются к ClickHouse, а окна за ними длиной в десять секунд.
</Callout>

## Детальный просмотр атаки

Щёлкните по атаке в списке **Активные и недавние атаки**, чтобы открыть её
выдвижную панель с деталями. Помимо классификации, разбора «почему сработало», лестницы эскалации
и маршрута подавления, источник трафика поясняют два раздела:

- **Захваченная выборка** — доминирующий **Топ источников** (для исходящей атаки переименован в
  **Топ назначений**), **Протоколы** и **Топ портов источника / назначения**, извлечённые из
  выборки потоков, плюс число пакетов в выборке. Когда включён GeoIP, добавляется строка
  **Топ AS** (для исходящих атак — **Топ AS назначения**): самые активные автономные системы по
  числу пакетов с поправкой на выборку, в формате `AS<номер> <организация>`.
- **Сырые потоки** — таблица отдельных захваченных потоков (источник, протокол, назначение,
  флаги, фрагментация, пакеты). Когда загружена база стран, у каждого источника появляется
  маленький бейдж кода страны, например `US` или `DE`; при наведении показывается организация
  (сеть) источника.

Строка **Топ AS** и бейджи стран в потоках появляются только при включённой атрибуции GeoIP.
Укажите в `geoip.asn_database` базу MaxMind GeoLite2/GeoIP2 ASN — для номеров AS и названий
организаций, а в `geoip.country_database` — базу стран для бейджей стран; см. блок `geoip` на
странице [Конфигурация](/docs/configuration). Без них панель всё равно отображается — просто без
строки AS и тегов стран.

## Аутентификация

По умолчанию API и панель управления не требуют аутентификации, что безопасно только потому,
что значение `api.listen` по умолчанию привязано к `127.0.0.1`. Когда вы задаёте API-токен,
панель управления адаптируется: статическая оболочка интерфейса по-прежнему загружается, но
данные за ней не появляются, пока вы не предоставите токен.

Когда аутентификация включена, панель управления запрашивает токен и хранит его в
`sessionStorage` браузера, добавляя его в виде заголовка bearer к каждому запросу к API, который
она выполняет. Каждый запрос `/api/v1` авторизуется с помощью `Authorization: Bearer <token>`;
`/metrics` и статическая оболочка остаются открытыми, а актуальные данные и элементы управления
блокировками / перезагрузкой — нет.

<Callout type="warning" title="Задайте токен перед тем, как открывать слушатель">
Прежде чем привязывать `api.listen` к чему-либо за пределами `127.0.0.1`, настройте API-токен.
См. [Аутентификация](/docs/authentication) о том, как задать `api.token_env` и как проверяются
запросы.
</Callout>
