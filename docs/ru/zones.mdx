# Справочник зон

**Файл зон** — это список сайтов, перед которыми стоят ваши [граничные узлы](/docs/edge): для
каждой зоны — её исходные серверы (origins), минимальная версия TLS, какой удостоверяющий центр
использовать и политика по запросам, которую применяет служба решений узла. Он живёт на мозге, в
собственном файле, названном в `edge.zones_file` в `kapkan.yaml`, потому что зоны — это данные
арендатора со своим ритмом изменений: файл загружается и проверяется вместе с конфигурацией, и
**сломанный файл зон оставляет в силе предыдущие зоны**, а не отдаёт наполовину сломанный документ.

```yaml
zones:
  - name: shop.example.com               # a lower-case hostname; no wildcards
    origins:                             # at least one host:port; IPv6 as [addr]:port
      - "10.0.0.10:8080"
      - "10.0.0.11:8080"
    tls:
      min_version: "1.2"                 # "1.2" (default) or "1.3"
    acme:
      directory: ""                      # this zone's CA; empty = the node's default
      fallback: ""                       # tried after repeated failures; empty = node default
    policy:
      mode: decide                       # decide (default) | none
      failure_mode: open                 # open (default) | closed
      challenge: "off"                   # only "off" today
      rate:
        rps: 50                          # requests per second per source; 0 = no ceiling
        concurrency: 20                  # in-flight requests per source; 0 = no ceiling
    extra_directives_file: ""            # optional nginx snippet, included last
```

Проверяйте командой `kapkan -check-config /etc/kapkan/config.yaml` (она следует за
`edge.zones_file`), а JSON-схему для редактора генерируйте командой `kapkan -dump-zones-schema` —
зафиксированная копия лежит в `docs/zones-schema.json` и перегенерируется командой
`make -C engine schema`; набор тестов падает на устаревшей копии.

## Ключи

| Ключ | Значение |
| --- | --- |
| `zones[].name` | Имя хоста зоны — в том виде, в котором на него будет выпущен сертификат: метки RFC 1123 в нижнем регистре, без подстановочных знаков (wildcard), без завершающей точки, не IP-адрес, не более 238 символов. Верхний регистр приводится к нижнему. Имена должны быть уникальны. |
| `zones[].origins[]` | Куда nginx проксирует запросы зоны: один или несколько upstream вида `host:port`, IPv6-адрес в квадратных скобках (`[2001:db8::10]:8080`), порт `1..65535` без ведущего нуля. Исходный сервер, заданный **именем хоста**, разрешается один раз — когда nginx загружает конфигурацию; имя, которое не разрешается, роняет всё поколение. Дубликаты отклоняются. |
| `zones[].tls.min_version` | Наименьшая версия TLS, которую принимает зона: `"1.2"` (по умолчанию) или `"1.3"`. При TLS 1.2 узел генерирует современный набор шифров ECDHE; при 1.3 — только наборы TLS 1.3. На nginx до 1.29.2 к каждой зоне применяется **наименьший** минимум из всех зон узла (побеждает `ssl_protocols` сервера по умолчанию); Angie и nginx ≥ 1.29.2 соблюдают его для каждой зоны отдельно. |
| `zones[].tls.h3` | HTTP/3. **Пока не поддерживается** — `true` отклоняется; опустите ключ или задайте `false`. |
| `zones[].acme.directory` | URL каталога ACME, в котором заказывается сертификат этой зоны (например, тестовый или частный CA). Пусто означает значение по умолчанию узла — боевой каталог Let's Encrypt, если `edge.yaml` узла не говорит иного. URL `http(s)` с хостом. |
| `zones[].acme.fallback` | Второй каталог, к которому узел обращается после трёх неудач подряд с основным (ответ на лимит дублирующих сертификатов для парка), далее чередуя их; успех у любого из них сбрасывает состояние неудач, и следующее продление снова начинает с основного. Должен отличаться от `acme.directory`. Пусто означает значение по умолчанию узла, которого может и не быть. CA, требующий привязки внешнего аккаунта (External Account Binding — ZeroSSL, Google Trust Services), нуждается в учётных данных в `edge.yaml` **узла** — файл зон не несёт секретов. |
| `zones[].policy.mode` | `decide` (по умолчанию): каждый запрос к зоне спрашивает службу решений узла через `auth_request` nginx. `none`: только проксирование — ни решений, ни частоты, ни меток; зона по-прежнему получает свой сертификат и свой лог доступа. |
| `zones[].policy.failure_mode` | Что делает nginx, когда служба решений упала, отвечает медленно или не по протоколу: `open` (по умолчанию) пропускает запрос без решения — аналог пропуска по умолчанию (default-pass) плоскости данных для граничного узла — и учитывает его; `closed` отвечает `503`. При `open` отказ поглощается внутри подзапроса, так что keepalive-соединение клиента его переживает; при `closed` nginx отвечает `503` по этому соединению. |
| `zones[].policy.challenge` | Проверки клиентов (challenge: proof-of-work, JavaScript) — следующий этап; сегодня принимается только `"off"`. |
| `zones[].policy.rate.rps` | Запросов в секунду на **источник** — IPv4-адрес или IPv6-подсеть `/64` — применяется службой решений с token bucket, чей всплеск равен одной секунде запросов. `0` (по умолчанию) не задаёт потолка. Изменение никогда не перезагружает nginx. |
| `zones[].policy.rate.concurrency` | Одновременных запросов на источник — подсчитываются приближённо по решениям и завершениям в логе доступа (у источника, чей поток лога затих, потолок приостанавливается, а не применяется ошибочно). `0` (по умолчанию) не задаёт потолка. |
| `zones[].extra_directives_file` | **Абсолютный** путь на узле к фрагменту конфигурации nginx, включаемому последним в сервер `:443` зоны, — единственная отдушина (лишний заголовок, свой `location`). Что он сломает — на вашей ответственности; единственный страж — `nginx -t`, и фрагмент, не прошедший его, оставляет обслуживать предыдущее поколение. В пути не допускаются пробелы, `;`, `#`, фигурные скобки, кавычки, обратная косая черта, `$` и символы подстановки (glob: `* ? [ ]`). |

## Что политика делает с запросом

При `mode: decide` nginx спрашивает службу решений узла перед проксированием. Ответ — `200` (запрос
уходит на исходный сервер, с установленным `X-Kapkan-Mark`, если источник несёт метку) или `403` с
причиной:

| Причина | Ответ nginx | Кем установлена |
| --- | --- | --- |
| `rate` | `429` с `Retry-After: 1` | Источник превысил `policy.rate.rps`. |
| `concurrency` | `429` с `Retry-After: 1` | У источника `policy.rate.concurrency` запросов в обработке. |
| `table:<reason>` | `403` | Источник в таблице вердиктов узла: переведён туда свёртками (`table:flood` — источник, который продолжал ломиться через потолок частоты, получает запрет на минуту, при повторе — удваивается до десяти) или, позже, лестницей мозга. Метка dry-run — `would-deny:table:<reason>`. |

Два заголовка находятся под контролем Kapkan и никогда не могут быть подделаны клиентом:
`X-Kapkan-Zone` (имя зоны) всегда доходит до исходного сервера; `X-Kapkan-Mark` присутствует,
лишь когда источник несёт метку, и отсутствует в остальных случаях — присланное клиентом значение
любого из них отбрасывается. Источник, чьи запросы почти сплошь `4xx`/`5xx`, получает метку
`errors`; в режиме **dry-run** каждый отказ, который состоялся бы, превращается в пропуск с меткой
`would-deny:<reason>`, так что исходный сервер видит ровно то, что отверг бы боевой режим.

Узел хранит ограниченное число источников на зону; когда таблица заполнена, новый источник
пропускается **без учёта** (пропуск по умолчанию) и подсчитывается — ему никогда не отказывают
из-за нехватки места.

## Сертификаты

Каждая зона получает сертификат **на каждом узле**, выпускаемый и продлеваемый на узле по HTTP-01;
закрытый ключ никогда не покидает машину. Продление начинается за 30 дней до истечения (за треть
срока жизни для более коротких сертификатов), со случайным разбросом по узлам и зонам. Пока не
получен первый сертификат, слушатель `:80` зоны отвечает `503` на всё, кроме пути вызова ACME, —
зона никогда не проксируется открытым текстом. Каждое имя выпускается явно; подстановочные имена
(wildcard, DNS-01) — следующий этап.
