# Плоскость отпечатков (JA4)

[Плоскость данных](/docs/dataplane) отбрасывает пакеты и ограничивает скорость по адресу и по форме
пакета рукопожатия. **Плоскость отпечатков** добавляет ещё одну ось: она опознаёт *клиента* за
рукопожатием по его отпечатку **JA4** и позволяет блокировать по источнику клиентов, чей отпечаток
вы внесли в список, — независимо от того, с какого адреса они приходят.

По своей конструкции она работает **вне пути обработки**. Ядро не принимает решений об отпечатке; оно
**копирует** ограниченный, выборочный префикс каждого TLS ClientHello и QUIC Initial в
пользовательское пространство через кольцевой буфер. Пользовательское пространство вычисляет JA4, и
если этот JA4 есть в вашем списке блокировок, оно устанавливает
[блокировку источника](/docs/dataplane#блокировки-источников-из-вашего-стека) на существующем пути XDP —
то же самое отбрасывание по источнику, которое оператор или интеграция устанавливают через API. Ядро
копирует; пользовательское пространство классифицирует; принуждение — это тот же путь блокировки
источника, который у вас уже есть.

<Callout type="info" title="Она работает поверх плоскости данных">
Плоскость отпечатков — часть `dataplane`: ей нужны `dataplane.enabled: true` и та же подготовка узла
([Плоскость данных в ядре](/docs/dataplane) — Linux 5.15+, drop-in для systemd, capabilities). По
умолчанию она **выключена**, даже когда плоскость данных включена.
</Callout>

## Что такое JA4

[JA4](https://github.com/FoxIO-LLC/ja4) (FoxIO, BSD-3) — это **клиентский** отпечаток TLS/QUIC вида
`a_b_c`:

```text
t13d1516h2_8daaf6152771_e5627efa2ab1
│└ version │ └ sha256(sorted ciphers)[:12]
│  SNI d/i │           └ sha256(sorted extensions "_" sigalgs)[:12]
└ transport: t = TLS-over-TCP, q = QUIC
```

Первый символ — это транспорт, поэтому отпечаток QUIC-клиента начинается с `q`, а тот же клиент поверх
TCP начинается с `t`; два хеша выводятся из списков шифров и расширений и не зависят от транспорта.
Kapkan вычисляет JA4 (и извлекает SNI и ALPN) с помощью чистого Go-парсера — без библиотеки, без
внешней службы. Для QUIC он сначала расшифровывает Initial версии v1 (см. ниже).

## Как это работает

1. **Копирование (ядро).** Когда плоскость данных распознаёт TLS ClientHello или QUIC v1 Initial,
   пофункциональный (per-CPU) **сэмплер** на основе token-bucket решает, копировать ли его. Копии
   попадают в кольцевой буфер; сэмплер ограничивает число копий в секунду на CPU, так что плоскость
   никогда не сможет стать собственным источником DoS при флуде рукопожатий.
2. **Классификация (пользовательское пространство).** Читатель опустошает кольцо, вычисляет JA4 и ищет
   его в списке блокировок. QUIC Initial сначала расшифровывается ключами, выведенными из его
   Destination Connection ID — публичные входные данные, без обмена секретами, — именно поэтому копии
   вне пути обработки достаточно.
3. **Принуждение.** Совпадение в списке блокировок устанавливает блокировку источника с TTL на
   заявленный источник в сторону жертвы, на том же пути XDP, что и блокировка источника через API.
   Ничего не анонсируется ни одному пиру.

Разбор и расшифровка **отказывают в открытую (fail open)**: усечённый снимок, рукопожатие,
разбитое на несколько пакетов, версия QUIC, отличная от v1, или что-либо, что не разбирается,
просто *не отпечатывается* — и никогда не классифицируется неверно. Плоскость никогда не пересобирает
данные между датаграммами, поэтому ClientHello больше одной захваченной датаграммы здесь отпечатать
нельзя.

## Настройка

Плоскость располагается под `dataplane.fingerprint`:

```yaml
dataplane:
  enabled: true
  interfaces: ["eth0"]
  fingerprint:
    enabled: true            # off by default; requires dataplane.enabled: true
    sample_pps: 1000          # copies/sec/CPU cap (the DoS-safety sampler); default 1000
    block_ttl_seconds: 300    # how long a JA4 block lives before it must refresh; default 300, max 86400
    ja4_blocklist:            # exact-match JA4 fingerprints to source-block on sight
      - t13d1516h2_8daaf6152771_e5627efa2ab1   # a TLS client
      # QUIC fingerprints start with q; add the ones your telemetry flags
```

| Ключ | Значение |
| --- | --- |
| `fingerprint.enabled` | Включает плоскость. **Требует `dataplane.enabled: true`** (иначе конфигурация отклоняется). По умолчанию выключено. Изменение переключает флаг ядра, записываемый при подключении, поэтому **требуется перезапуск**. |
| `fingerprint.sample_pps` | Ограничение на число копий рукопожатий в секунду на CPU — сэмплер в ядре, удерживающий плоскость в границах при флуде. `0` выбирает значение по умолчанию (1000). **Требуется перезапуск.** |
| `fingerprint.block_ttl_seconds` | Как долго блокировка источника, вызванная JA4, живёт в ядре, прежде чем её нужно обновить. `0` выбирает значение по умолчанию (300); должно быть в пределах `[1, 86400]`. **Применяется на лету.** |
| `fingerprint.ja4_blocklist` | Отпечатки JA4 для блокировки по источнику, сопоставляемые **точно** (`a_b_c`). Отпечатки QUIC начинаются с `q`. Дубликаты отклоняются. **Применяется на лету** — правка списка вступает в силу на следующем рукопожатии, без перезапуска. |

Список блокировок и TTL применяются на лету; флаг включения и частота сэмплера записываются в ядро
при подключении и требуют перезапуска. [Конструктор конфигурации](https://kapkan.io/config)
отображает эти поля на расширенном шаге плоскости данных.

## Блокировка JA4 действует на *заявленный* источник

Это ключевая оговорка, и именно она определяет, как следует читать список блокировок.

ClientHello распознаётся **бесконтекстным (stateless) сопоставлением по фиксированному смещению** —
за ним нет завершённого TCP-рукопожатия, — поэтому единственный **подменённый (spoofed)** пакет,
несущий сфабрикованный ClientHello, чей JA4 вы внесли в список блокировок, заблокирует по источнику
любой адрес, который этот пакет заявляет источником. Это модель блокировки источника, работающая
ровно так, как задумано (она действует на адрес на проводе), но при триггере, который может
сфабриковать атакующий, это означает, что список блокировок JA4 можно превратить в рычаг для
блокировки трафика выбранной третьей стороны в сторону жертвы.

<Callout type="warning" title="Читайте список блокировок как «блокировать заявленные источники этого отпечатка»">
Запись в списке блокировок JA4 — это **не** утверждение о том, что узел вреден. Воспринимайте её как
«блокировать источники, предъявляющие этот отпечаток», зная, что отпечаток — а значит, и источник, на
который он ложится, — можно подменить. Каждая блокировка отпечатка имеет TTL и учитывает
[dry-run](/docs/going-live), так что ошибочное срабатывание само устаревает.
</Callout>

Чтобы ограничить сопутствующий ущерб, блокировки плоскости отпечатков черпают из **отдельного,
меньшего бюджета**, чем блокировки источника от оператора и API, — половины пула привязок к
источнику. Флуд пакетов со сфабрикованным JA4 может заполнить только собственную резервацию и
**никогда** не сможет истощить блокировки источника оператора/API, которые делят этот пул.

## Аудит

Блокировка плоскости отпечатков записывается в [журнал аудита](/docs/audit) как запись `source_block`
с `source: "auto"` — действие совершил движок, а не оператор, поэтому она не несёт оператора, роли или
арендатора. Её причина — совпавший отпечаток, например
`ja4:t13d1516h2_8daaf6152771_e5627efa2ab1`. В аудит попадают только успешные блокировки (блокировка в
режиме dry-run фиксируется и помечается); отказы учитываются в метриках и логах, но не пишутся в
хранилище аудита, так что флуд с подменённым JA4 не сможет его засорить.

## Метрики

| Метрика | Метки | Значение |
| --- | --- | --- |
| `kapkan_fingerprint_events_total` | `result` | События кольца по исходу: `classified`, `blocked`, `would_block` (совпадение в режиме dry-run), `suppressed` (повтор в пределах остывания блокировки), `block_error` (отказ по политике — в белом списке / защищён / бюджет исчерпан), `unparsed`, `malformed`, `unknown_axis`, `panic`. |
| `kapkan_dataplane_observations_total` | `kind="fp_emitted"` | Рукопожатия, скопированные сэмплером в пользовательское пространство. |
| `kapkan_dataplane_observations_total` | `kind="fp_throttled"` | Рукопожатия, отброшенные сэмплером ради удержания под `sample_pps` — ожидаемо растёт при флуде, пока `fp_emitted` выходит на плато. |
| `kapkan_dataplane_observations_total` | `kind="fp_ring_full"` | Копии, отброшенные из-за того, что пользовательское пространство не опустошало кольцо достаточно быстро. Устойчиво ненулевая частота здесь означает, что читатель не успевает. |

См. [Метрики](/docs/metrics) для полного семейства метрик плоскости данных и того, как наблюдения
соотносятся с итоговыми вердиктами.

## Ограничения

- **Только QUIC v1.** QUIC v2 и черновые версии используют другие ключи и не расшифровываются; их
  Initial-пакеты копируются и отбрасываются, но не отпечатываются.
- **Одна датаграмма.** Рукопожатие, охватывающее несколько пакетов или датаграмм, не пересобирается,
  поэтому очень большой ClientHello (много расширений, крупные постквантовые key share) может выйти за
  захваченный префикс и остаться неотпечатанным. Это отказ в открытую, а не блокировка.
- **Требует плоскость данных.** `dataplane.enabled: true` и ядро 5.15+ с drop-in.
