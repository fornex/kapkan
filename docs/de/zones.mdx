# Zonen-Referenz

Die **Zonen-Datei** ist die Liste der Websites, vor denen Ihre [Edge-Knoten](/docs/edge) stehen:
für jede Zone ihre Origins, ihre TLS-Untergrenze, welche Zertifizierungsstelle zu verwenden ist
und die Richtlinie pro Anfrage, die der Entscheidungsdienst des Knotens durchsetzt. Sie liegt auf
dem Gehirn, in einer eigenen Datei, die `edge.zones_file` in `kapkan.yaml` benennt, denn Zonen
sind Mandantendaten mit eigenem Änderungsrhythmus — die Datei wird zusammen mit der Konfiguration
geladen und validiert, und **eine defekte Zonen-Datei hält die vorherigen Zonen live**, statt ein
halb defektes Dokument auszuliefern.

```yaml
zones:
  - name: shop.example.com               # a lower-case hostname; no wildcards
    tenant: "shop"                       # optional owner label (multi-tenancy); absent = house zone
    hostgroup: edge-eu                   # optional placement: served by nodes listing this group; absent = global
    origins:                             # at least one host:port; IPv6 as [addr]:port
      - "10.0.0.10:8080"
      - "10.0.0.11:8080"
    tls:
      min_version: "1.2"                 # "1.2" (default) or "1.3"
      h3: false                          # true = also serve over HTTP/3 (QUIC) where the node can
      # h3_options: { advertise: true, alt_svc_max_age_seconds: 86400 }  # only with h3: true
    acme:
      directory: ""                      # this zone's CA; empty = the node's default
      fallback: ""                       # tried after repeated failures; empty = node default
    policy:
      mode: decide                       # decide (default) | none
      failure_mode: open                 # open (default) | closed
      dry_run: false                     # true = this zone is watch-only on every node
      challenge: auto                    # off (default) | manual | auto — the proof-of-work rung
      challenge_options:
        dry_run: true                    # true (default) = the rung only shows who it would ask
        exempt_paths: ["/healthz", "/api/"]
        difficulty: 18                   # 12..22 leading zero bits
        cookie_ttl_seconds: 1800         # how long a clearance lasts, 60..86400
        auto:
          zone_rps: 2000                 # zone-wide challenge at this admitted rate per node; 0 = off
          hold_seconds: 300              # how long the zone stays under challenge, 30..3600
      rate:
        rps: 50                          # requests per second per source; 0 = no ceiling
        concurrency: 20                  # in-flight requests per source; 0 = no ceiling
    extra_directives_file: ""            # optional nginx snippet, included last
```

Validieren Sie mit `kapkan -check-config /etc/kapkan/config.yaml` (es folgt `edge.zones_file`),
und erzeugen Sie das JSON-Schema für Ihren Editor mit `kapkan -dump-zones-schema` — die
eingecheckte Kopie ist `docs/zones-schema.json`, neu erzeugt mit `make -C engine schema`; die
Testsuite schlägt bei einer veralteten Kopie fehl.

## Schlüssel

| Schlüssel | Bedeutung |
| --- | --- |
| `zones[].name` | Der Hostname der Zone, so wie das Zertifikat dafür ausgestellt wird: kleingeschriebene RFC-1123-Labels, kein Wildcard, kein abschließender Punkt, keine IP-Adresse, höchstens 238 Zeichen. Großbuchstaben werden in Kleinbuchstaben umgewandelt. Namen müssen eindeutig sein. |
| `zones[].tenant` | Optionales Eigentums-Label, auf derselben Achse wie das `tenant` einer Hostgroup (`[A-Za-z0-9._-]`, höchstens 64 Zeichen). Ein darauf tenant-bezogenes [API-Token](/docs/multi-tenancy) sieht die Zone in `GET /api/v1/edge/zones/status`, liest ihre [Edge-Historie](/docs/api#get-apiv1edgehistory) und ihre aussagekräftigen Quellen und darf als Operator ihren [Hebel](/docs/edge#der-hebel) ziehen; eine Zone ohne Label ist nur für ungebundene Tokens sichtbar. Eigentum, nicht Platzierung, und niemals vererbt — auch nicht vom Top-Level-`tenant` der kapkan.yaml. Ein Token darf an einen Mandanten gebunden sein, den nur Zonen verwenden: ein reiner Edge-Kunde mit Hostnamen und ohne Präfixe. Das Label gelangt nie in das Dokument, das die Knoten rendern — die Zonen einer Flotte zu labeln löst also keinen Reload aus. |
| `zones[].hostgroup` | Wo die Zone bedient wird ([Zonen auf Knoten verteilen](/docs/edge#zonen-auf-knoten-verteilen)): der Name einer Hostgroup in der `kapkan.yaml` oder `global`. Ein Knoten bedient die Zone, wenn seine `edge.nodes[].hostgroups` diese Gruppe auflisten; fehlt der Schlüssel, liegt die Zone in der **globalen** Gruppe und wird von jedem Knoten bedient, der `global` auflistet — also von jedem Knoten ohne Geltungsbereich. Ein Label allein nimmt die Zone somit von jedem Knoten, der es nicht auflistet, und eine Flotte, die nie eines gesetzt hat, bleibt unberührt. Die Hostgroup muss existieren (geprüft, wenn das Gehirn beide Dateien lädt — ein Tippfehler würde die Zone nirgends ausliefern), und wenn sowohl die Gruppe als auch die Zone ein `tenant` tragen, müssen sie übereinstimmen; nichts wird vererbt. Platzierung ist nicht Eigentum (`tenant`) und gelangt nie in das Dokument: Jeder Knoten erhält genau die Zonen, die sein Geltungsbereich abdeckt. |
| `zones[].origins[]` | Wohin nginx die Anfragen der Zone per Proxy weiterreicht: ein oder mehrere `host:port`-Upstreams, eine IPv6-Adresse in eckigen Klammern (`[2001:db8::10]:8080`), der Port `1..65535` ohne führende Null. Ein **Hostnamen**-Origin wird einmal aufgelöst, wenn nginx die Konfiguration lädt; einer, der sich nicht auflösen lässt, lässt die gesamte Generation fehlschlagen. Duplikate werden abgelehnt. |
| `zones[].tls.min_version` | Die niedrigste TLS-Version, die die Zone akzeptiert: `"1.2"` (Standard) oder `"1.3"`. Mit TLS 1.2 rendert der Knoten den modernen ECDHE-Cipher-Satz; mit 1.3 nur TLS-1.3-Suiten. Auf nginx vor 1.29.2 gilt die **niedrigste** Untergrenze aller Zonen eines Knotens für jede Zone (die `ssl_protocols` des Default-Servers gewinnen); Angie und nginx ≥ 1.29.2 respektieren sie pro Zone. |
| `zones[].tls.h3` | `true` liefert die Zone neben TLS über TCP auch über HTTP/3 aus (QUIC, UDP 443), `false` (Standard) nicht. Gerendert nur auf den Knoten, deren nginx oder Angie `--with-http_v3_module` trägt und deren `edge.yaml` nicht `quic.h3: off` sagt; anderswo wird die Zone über TCP ausgeliefert und der Report des Knotens benennt sie (`terminator.h3.unsupported`; die Zeile der Zone in `GET /api/v1/edge/zones/status` führt den Knoten unter `h3.unsupported` auf, eine Zone mit `mode: none` eingeschlossen). Die Zone braucht zuerst ihr Zertifikat (kein TLS-Server, kein QUIC). `h3` und `h3_options` sind gerenderte Konfiguration, wie `origins` und `tls.min_version`: Sie zu ändern bedeutet eine neue getestete Generation und einen Reload auf jedem Knoten; die Regler des schnellen Pfads (`policy.rate`, `policy.challenge`, `dry_run`, der Hebel) ändern nie gerenderte Bytes. **Aktualisieren Sie zuerst die Knoten**: Ein Knoten älter als dieses Release lehnt ein Dokument ab, das `h3` trägt, bleibt mit `converged: false` auf seiner vorherigen Generation und kann danach nichts mehr installieren — erneuerte Zertifikate eingeschlossen —, bis `h3` entfernt oder der Knoten aktualisiert ist. Retry ist standardmäßig an und 0-RTT aus, knotenweit durch nginx' Bauart; `quic.retry` in der `edge.yaml` des Knotens ist der einzige Ort, an dem Retry abgeschaltet werden kann. |
| `zones[].tls.h3_options.advertise` | `true` (Standard) kündigt HTTP/3 mit einem `Alt-Svc`-Header auf den TLS-über-TCP-Antworten der Zone an; `false` rendert den QUIC-Listener, ohne ihn anzukündigen — der Kanarienvogel: Nur Clients, die mit dem Namen schon HTTP/3 sprechen, erreichen ihn (`curl --http3-only`), Browser bleiben auf TCP. Ein Transport hat keinen Beobachtungsmodus; das hier ist der ehrliche Ersatz. Es zu ändern ist ein Reload. Ohne `tls.h3: true` abgelehnt. |
| `zones[].tls.h3_options.alt_svc_max_age_seconds` | Das `ma` von `Alt-Svc`: wie lange ein Client sich die Alternative merken darf, `60..604800` (Standard `86400`). Ein kurzer Wert ist der Rollout-Schritt zwischen dem stillen Kanarienvogel und dem Standard, und er begrenzt, wie lange Browser HTTP/3 noch versuchen, nachdem Sie es abgeschaltet haben. Es zu ändern ist ein Reload. Ohne `tls.h3: true` abgelehnt. |
| `zones[].acme.directory` | Die URL des ACME-Verzeichnisses, bei dem das Zertifikat dieser Zone bestellt wird (zum Beispiel eine Staging- oder private CA). Leer bedeutet den Standard des Knotens, also Let's Encrypt Production, sofern die `edge.yaml` des Knotens nichts anderes sagt. Eine `http(s)`-URL mit Host. |
| `zones[].acme.fallback` | Ein zweites Verzeichnis, zu dem ein Knoten nach drei aufeinanderfolgenden Fehlschlägen mit dem primären wechselt (die Antwort auf eine Duplikat-Zertifikat-Obergrenze in einer Flotte) und von da an abwechselt; ein Erfolg bei einem der beiden löscht den Fehlerzustand, und die folgende Erneuerung versucht zuerst das primäre. Muss sich von `acme.directory` unterscheiden. Leer bedeutet den Standard des Knotens, der auch keiner sein kann. Eine CA, die ein External Account Binding verlangt (ZeroSSL, Google Trust Services), braucht ihre Zugangsdaten in der `edge.yaml` des **Knotens** — die Zonen-Datei trägt keine Geheimnisse. |
| `zones[].policy.mode` | `decide` (Standard): Jede Anfrage an die Zone fragt über den `auth_request` von nginx den Entscheidungsdienst des Knotens. `none`: nur Proxy — keine Entscheidung, keine Rate, keine Markierungen; die Zone erhält trotzdem ihr Zertifikat und ihr Zugriffsprotokoll. |
| `zones[].policy.failure_mode` | Was nginx tut, wenn der Entscheidungsdienst ausgefallen, langsam oder außerhalb des Vertrags ist: `open` (Standard) lässt die Anfrage unentschieden durch — das Edge-Gegenstück zum Default-Pass der Datenebene — und zählt sie; `closed` antwortet `503`. Mit `open` wird der Fehler innerhalb der Subrequest abgefangen, sodass die Keepalive-Verbindung des Clients ihn überlebt; mit `closed` antwortet nginx auf dieser Verbindung mit `503`. |
| `zones[].policy.dry_run` | `true` macht **diese Zone** auf jedem Knoten nur beobachtend: Ihre Sperren und Challenges werden gezählt und markiert (`would-deny:<reason>`, `would-challenge:<why>`), keine wird durchgesetzt, während die Schwesterzonen wie zuvor durchsetzen. Der eigene `dry_run` des Knotens (`edge.yaml`) ist der Boden, unter den eine Zone nicht gehen kann — eine Zone kann gegenüber ihrem Knoten nur *mehr* beobachten, nie weniger. Standard `false`: Die Zone folgt ihrem Knoten. Ein Knoten, der älter ist als dieses Release, kennt den Schlüssel nicht und setzt die Zone unter seinem eigenen `dry_run` durch; aktualisieren Sie zuerst die Knoten. |
| `zones[].policy.challenge` | Die Proof-of-Work-Stufe ([die Freigabeseite](/docs/edge#die-freigabeseite)): `off` (Standard), `manual` oder `auto`. **`manual`**: Jede Anfrage ohne gültige Freigabe wird auf die Seite geschickt. **`auto`**: Eine Quelle wird herausgefordert, wenn die Rollups des Knotens es sagen — ein Flooder wird *herausgefordert, bevor er gesperrt wird*, und die ganze Zone, wenn `challenge_options.auto.zone_rps` auslöst — oder wenn ein Betreiber [den Hebel](/docs/edge#der-hebel) zieht. Eine gültige Freigabe passiert die Stufe, niemals die Ratenobergrenze. Nur beobachtend, bis `challenge_options.dry_run` `false` ist. Eine Änderung lädt nginx niemals neu. |
| `zones[].policy.challenge_options.dry_run` | Der eigene Nur-beobachten-Schalter der Stufe, **standardmäßig `true`**: Eine Challenge wird als Allow mit der Markierung `would-challenge:<why>` beantwortet, sodass Sie sehen, wer gefragt worden *wäre*, bevor irgendeine Zone irgendjemanden fragt. Setzen Sie `false`, damit die Stufe greift (der `dry_run` des Knotens und der der Zone gewinnen weiterhin). |
| `zones[].policy.challenge_options.exempt_paths[]` | Anfragepfad-Präfixe, die die Stufe niemals herausfordert — Health-Checks, API-Clients, Webhooks: absolute Pfade, verglichen als Präfixe des Anfragepfads ohne seine Query, sowohl in der normalisierten als auch in der rohen Form (ein Pfad mit einem Punkt-Segment, `;`, einem Backslash, einem Steuerbyte oder einem übrig gebliebenen `%`-Escape ist niemals ausgenommen). Die eine Stelle, an der der Edge einen Pfad liest, nur für eine Ausnahme — niemals für ein Verdikt. Höchstens 64. |
| `zones[].policy.challenge_options.difficulty` | Die führenden Nullbits des Rätsels, `12..22` (Standard `18`: ein paar Sekunden in den Worker-Bahnen eines Browsers; jeder Schritt verdoppelt die Arbeit). Ein langsames Gerät muss trotzdem innerhalb des Zwei-Minuten-Fensters des Rätsels fertig werden; die Seite bietet neben einem langen Lösen den zeitgesteuerten Pfad ohne JavaScript an. |
| `zones[].policy.challenge_options.cookie_ttl_seconds` | Wie lange die Freigabe eines gelösten Rätsels gilt, `60..86400` (Standard `1800`). Ein freigegebener Client löst erneut, wenn sie abläuft oder wenn sich seine Adresse (IPv6: `/64`) ändert. Die Freigabe des Tickets ohne JavaScript ist fest auf fünf Minuten gesetzt. |
| `zones[].policy.challenge_options.auto.zone_rps` | Für `challenge: auto`: die **zugelassene** Anfragerate der Zone auf einem Knoten — entschiedene Anfragen, die der Knoten nicht abgewiesen hat —, ab der jede Quelle der Zone herausgefordert wird (die Flut, die über so viele Quellen verteilt ist, dass keine ihre eigene Obergrenze auslöst). `0` (Standard) setzt keinen zonenweiten Auslöser. Knotenlokal: Jeder Knoten misst sein eigenes Fenster. |
| `zones[].policy.challenge_options.auto.hold_seconds` | Wie lange die zonenweite Challenge nach einem Fenster, das sie ausgelöst hat, aktiv bleibt, `30..3600` (Standard `300`); jedes Fenster, das weiterhin über der Rate liegt, verlängert sie, und sie läuft von selbst ab. |
| `zones[].policy.rate.rps` | Anfragen pro Sekunde pro **Quelle** — eine IPv4-Adresse oder ein IPv6-`/64` — durchgesetzt vom Entscheidungsdienst mit einem Token-Bucket, dessen Burst dem Wert einer Sekunde entspricht. `0` (Standard) setzt keine Obergrenze. Eine Änderung lädt nginx niemals neu. |
| `zones[].policy.rate.concurrency` | Gleichzeitig laufende Anfragen pro Quelle, näherungsweise gezählt aus Entscheidungen und Abschlüssen im Zugriffsprotokoll (bei einer Quelle, deren Log-Strom verstummt, wird die Obergrenze ausgesetzt statt fälschlich durchgesetzt). `0` (Standard) setzt keine Obergrenze. |
| `zones[].extra_directives_file` | Ein **absoluter** Pfad auf dem Knoten zu einem nginx-Snippet, das als Letztes in den `:443`-Server der Zone eingebunden wird — der eine Notausgang (ein zusätzlicher Header, eine eigene Location). Was es kaputt macht, verantworten Sie; `nginx -t` ist der einzige Schutz, und ein Snippet, das daran scheitert, lässt die vorherige Generation weiter bedienen. Keine Leerzeichen, `;`, `#`, geschweiften Klammern, Anführungszeichen, Backslash, `$` oder Glob-Zeichen (`* ? [ ]`) im Pfad. |

## Was eine Richtlinie mit einer Anfrage macht

Mit `mode: decide` fragt nginx den Entscheidungsdienst des Knotens, bevor es weiterreicht. Die
Antwort ist `200` — die Anfrage geht an den Origin, mit gesetztem `X-Kapkan-Mark`, wenn die Quelle
eine Markierung trägt —, `401` — die Quelle muss zuerst die Stufe überwinden, sodass nginx anstelle
des Origins [die Freigabeseite](/docs/edge#die-freigabeseite) ausliefert — oder `403` mit einem
Grund:

| Grund | nginx antwortet | Gesetzt durch |
| --- | --- | --- |
| `rate` | `429` mit `Retry-After: 1` | Die Quelle hat `policy.rate.rps` überschritten. |
| `concurrency` | `429` mit `Retry-After: 1` | Die Quelle hat `policy.rate.concurrency` Anfragen gleichzeitig laufen. |
| `table:<reason>` | `403` | Die Quelle steht in der Verdikt-Tabelle des Knotens: hochgestuft durch die Rollups (`table:flood` — eine Quelle, die weiter gegen ihre Ratenobergrenze gedrückt hat, wird für eine Minute gesperrt, bei Wiederholung verdoppelt bis auf zehn). Die Dry-Run-Markierung ist `would-deny:table:<reason>`. |
| `challenge:manual` | die Freigabeseite (`403`, niemals gecacht) | `policy.challenge: manual` — oder ein manueller [Hebel](/docs/edge#der-hebel) — und die Anfrage trägt keine gültige Freigabe. |
| `challenge:zone:<reason>` | die Freigabeseite | Die ganze Zone steht unter ihrem `auto.zone_rps`-Auslöser (`zone-rps`). |
| `challenge:table:<reason>` | die Freigabeseite | Die Quelle steht mit einer Challenge in der Verdikt-Tabelle: die Flut-Regel der Rollups in einer `auto`-Zone (`table:flood`) — die Stufe, die ein Flooder vor der Sperre bekommt. |

Eine Anfrage, die die Stufe überwindet, erreicht den Origin mit der Markierung `cleared` (oder
`cleared:nojs` für das zeitgesteuerte Ticket ohne JavaScript) — die Ratenobergrenze gilt für sie
weiterhin. Eine Quelle, die weiter flutet, während sie herausgefordert ist, oder die die Stufe
überwunden hatte und trotzdem flutet, wird gesperrt.

Zwei Header stehen unter Kapkans Kontrolle und können von einem Client niemals gefälscht werden:
`X-Kapkan-Zone` (der Zonenname) erreicht den Origin immer; `X-Kapkan-Mark` ist nur vorhanden, wenn
die Quelle eine Markierung trägt, und fehlt sonst — ein vom Client gesendeter Wert eines der beiden
wird verworfen. Eine Quelle, deren Anfragen fast ausschließlich `4xx`/`5xx` sind, wird mit `errors`
markiert. Im **Dry-Run** sieht der Origin genau, was der Echtbetrieb abgewiesen oder gefragt hätte:
Unter dem `dry_run` des Knotens oder dem `policy.dry_run` der Zone wird jede eigentlich fällige
Abweisung zu einem Allow, das mit `would-deny:<reason>` markiert ist, und jede eigentlich fällige
Challenge zu einem, das mit `would-challenge:<why>` markiert ist; unter dem eigenen
`challenge_options.dry_run` der Stufe wird nur die Challenge als Vorschau gezeigt
(`would-challenge:<why>`), während Obergrenze und Sperre wie zuvor greifen.

Der Knoten hält eine begrenzte Anzahl Quellen pro Zone; ist die Tabelle voll, wird eine neue
Quelle **unverfolgt** durchgelassen (Default-Pass) und gezählt, niemals aus Platzmangel abgewiesen.

## Zertifikate

Jede Zone erhält ein Zertifikat **pro Knoten**, ausgestellt und erneuert auf dem Knoten per
HTTP-01; der private Schlüssel verlässt die Box nie. Die Erneuerung beginnt 30 Tage vor Ablauf
(ein Drittel der Laufzeit bei kürzeren Zertifikaten), mit Jitter pro Knoten und Zone. Bis das erste
Zertifikat eintrifft, antwortet der `:80`-Listener der Zone auf alles außer dem ACME-Challenge-Pfad
mit `503` — eine Zone wird niemals im Klartext per Proxy weitergereicht. Jeder Name wird explizit
ausgestellt; Wildcards (DNS-01) sind ein späterer Meilenstein.

Die CA erreicht die Zone über ihre **öffentliche Adresse**, genau wie ein Besucher es tut, und das
Gehirn veröffentlicht die ausstehende Challenge im Dokument jedes Knotens, auf dem die Zone
[platziert ist](/docs/edge#zonen-auf-knoten-verteilen) — welcher von ihnen die Validierung auch
trifft, er beantwortet sie. Die Folgerung ist die, die weh tut: Eine Zone, deren Name nicht auf
einen Knoten auflöst, der sie bedient, kann überhaupt nicht ausgestellt werden, und ein Knoten
außerhalb der Platzierung weist die Verbindung ab, statt den Challenge-Pfad zu beantworten. Richten
Sie den Namen auf die Platzierung, bevor Sie ein Zertifikat erwarten. Eine Validierung hinterlässt
außerdem eine Spur: Die Prüfungen der CA sind eine Handvoll Anfragen in den Fenstern der Zone,
unentschiedene `2xx` — deshalb ist die [Historie](/docs/storage#edge-historie) einer untätigen Zone
rund um eine Ausstellung nicht ganz leer.
